# 任务备份包 XML 文件命名

## 目标

让 ZIP 导出/备份包内的任务 XML 文件可直接通过文件名识别，而不是使用 `0001.xml` 等序号。

## 确认的规则

- 每个任务 XML 仍存放在 ZIP 的 `tasks/` 目录内。
- 文件名由完整任务路径扁平化而成：目录分隔符 `\\` 转为 `_`，并保留 `.xml` 后缀。
- 例：`\生成日志` 写为 `tasks/生成日志.xml`；`\DouyinUser\DouyinGuard\LaunchDouyinGuard` 写为 `tasks/DouyinUser_DouyinGuard_LaunchDouyinGuard.xml`。
- Windows 不允许的文件名字符替换为 `_`；首尾空格和句点移除。
- 不同任务路径扁平化后重名时，按导出排序稳定追加 `_2`、`_3` 等序号。
- `manifest.json` 继续保存原始完整任务路径、ZIP 内文件路径和 SHA-256；导入仍以清单/XML 的原始任务路径为准，不根据文件名恢复任务名。

## 兼容性与边界

- 读取既有序号命名 ZIP 包的逻辑不变，因为导入依据 `manifest.json` 的 `file` 字段。
- 不增加目录层级，不改变 ZIP 格式版本、XML 内容、导入碰撞策略或“备份全部”范围。
- ZIP 条目路径仅使用正斜杠，继续经过既有安全路径校验。

## 验证

- 测试根目录任务和嵌套目录任务生成的扁平 XML 文件名。
- 测试非法字符清洗与稳定重名后缀。
- 测试新名称 ZIP 可往返读取，且旧 `tasks/0001.xml` 清单仍可读取。
