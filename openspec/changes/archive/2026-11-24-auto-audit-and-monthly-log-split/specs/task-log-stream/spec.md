# Spec Delta

## MODIFIED Requirements

### Requirement: 系统调度历史通道状态检测与自愈
系统 SHALL 检测当前 Windows 系统的 `Microsoft-Windows-TaskScheduler/Operational` 日志通道是否处于启用状态；若未启用，系统 SHALL 提供友好的状态提示与一键启用入口。在新建任务与修改任务时，系统 SHALL 默认提供开启日志审计选项，并在保存任务时确保底层日志通道处于启用状态。

#### Scenario: 检测到日志通道已启用
- **WHEN** 用户打开运行历史面板且系统通道 `enabled: true`
- **THEN** 系统正常加载并展示任务执行历史记录列表

#### Scenario: 检测到日志通道未启用并触发一键启用
- **WHEN** 系统通道处于禁用状态
- **THEN** 界面显示醒目的提示信息与“启用执行历史记录”按钮，用户点击后以管理员权限调用系统命令开启通道

#### Scenario: 新建任务保存时默认自动确保开启日志审计通道
- **WHEN** 用户在向导中新建定时任务并提交保存（保持默认勾选开启日志审计）
- **THEN** 系统在保存任务配置的同时检测若底层事件通道未开启则自动调用命令启用，确保该任务的运行历史可被记录

#### Scenario: 修改任务保存时默认自动确保开启日志审计通道
- **WHEN** 用户在向导中修改已有定时任务并提交保存（保持默认勾选开启日志审计）
- **THEN** 系统在更新任务配置时同样确保底层事件通道处于开启状态

### Requirement: 本地管理运维操作审计流
系统 SHALL 将本管理工具内执行的创建、修改、删除、启动、停止、导入等管理操作，以 JSON Lines 格式异步追加记录至本地按月份拆分的日志文件中（格式为 `logs/audit_YYYY-MM.jsonl`），并支持跨月份文件的倒序检索与合并读取。

#### Scenario: 手动触发或修改任务时写入审计日志
- **WHEN** 运维人员通过本工具创建新任务、修改配置或点击“运行”按钮
- **THEN** 系统异步向当前月份对应的 `logs/audit_YYYY-MM.jsonl` 追加一条包含操作时间戳、操作人、动作类型、目标任务路径和执行结果的 JSON 记录，且不阻塞主 UI 线程响应

#### Scenario: 按月份自动拆分写入操作审计日志
- **WHEN** 系统产生新的操作审计事件且跨入新的自然月
- **THEN** 系统自动切换写入至新月份命名的 `logs/audit_YYYY-MM.jsonl` 文件中，历史月份文件保持独立归档

#### Scenario: 跨月份倒序聚合读取与旧版文件兼容
- **WHEN** 用户在界面查看“操作审计”或触发导出全部审计记录
- **THEN** 系统自动扫描 `logs/` 目录下所有匹配的按月拆分文件及历史 `audit.jsonl`，按时间从最新到最旧依次聚合读取
