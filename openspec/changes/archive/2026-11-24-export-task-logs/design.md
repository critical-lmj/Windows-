# Design

## Context

定时任务管理器已具备基于 Windows 事件日志的执行历史采集与本地 JSON Lines 操作审计记录。为满足运维排查、离线报表及人工分析需求，需提供可视化的日志导出交互。详见 `proposal.md`。

## Goals / Non-Goals

**Goals:**
- 提供主界面一键【导出日志】交互入口。
- 将执行历史流与审计日志导出为通用的 CSV 格式。
- 写入 UTF-8 BOM（`\xef\xbb\xbf`），确保 Microsoft Excel 在中文系统下直接双击打开不乱码。
- 导出操作本身纳入操作审计记录流。

**Non-Goals:**
- 不引入第三方 Excel 库（如 xlsx 生成库），保持零依赖和轻量化。
- 不提供复杂的自定义字段过滤构建器，保持一键导出的简洁性。

## Decisions

### 决策 1：基于当前面板上下文判定导出目标
- **选择**：
  - 用户处于【运行历史】面板时：导出选中任务（或当前系统）的执行历史。
  - 用户处于【操作审计】面板时：导出选中任务（或全局）的审计记录。
  - 用户处于【详情】面板时：若选中了任务，优先导出该任务的执行历史。
- **理由**：符合直觉，无需弹出一大堆复杂的选择单选框，直观高效。

### 决策 2：采用 UTF-8 BOM 编码输出 CSV
- **选择**：在文件开头写入 `[]byte{0xEF, 0xBB, 0xBF}`，后接标准 `encoding/csv` 写入的数据。
- **理由**：Windows 平台上的 Excel 默认将无 BOM 的 UTF-8 识别为 ANSI，容易导致中文字符乱码；带 BOM 的 UTF-8 是 Windows 事实上的跨软件标准。

## Risks / Trade-offs

- **[风险] 导出路径被占用或权限不足**
  - $\rightarrow$ 缓解措施：捕获文件创建与写入错误，通过弹窗明确反馈，并在审计流中标记失败原因。
