# Design

## Context

Windows 任务计划程序中的任务既包含用户在根目录或自定义文件夹创建的业务任务，也包含上百个 Windows 内置系统级任务（集中在 `\Microsoft\Windows\...` 等目录下）。此前仅通过向导新建或修改任务时才会开启日志审计，存量自定义任务和系统级任务缺乏统一、精准的区分和差异化管理机制。

## Goals / Non-Goals

**Goals:**
- 自动区分自定义定时任务与系统级定时任务。
- 存量及新增自定义定时任务全部默认开启日志审计。
- 系统级定时任务保留默认不开启状态，支持随时手动开启。
- 将用户手动覆盖的审计开关状态持久化存储于 `logs/audit_policy.json`。
- 任务列表加载时，只要存在已开启审计的任务即自动自愈启用底层 `Microsoft-Windows-TaskScheduler/Operational` 事件通道（仅存在未开启审计的系统任务时不改变系统默认通道）。

**Non-Goals:**
- Windows 事件查看器自身底层日志通道无法按单个任务路径过滤写入，因此通道启用仍作用于系统通道，但在本软件的 UI 展示、审计检查、运行历史查询及导出入口中严格遵守单任务审计策略。

## Decisions

### 1. 系统级任务判定规则 (`isSystemTask`)
- 规范化任务路径与位置（将 `/` 转为 `\`、统一小写）：
  - 若任务完整路径以 `\microsoft\` 开头，或所在位置等于 `\microsoft` / 以 `\microsoft\` 开头，判定为系统级任务；
  - 若任务作者（`Author`）以 Windows MUI 资源引用前缀 `$(@` 开头，判定为系统级任务；
  - 其余根目录 `\` 或用户自建目录（如 `\Backup\...`）中的任务判定为自定义任务（用户自己设置的定时任务）。
- **原因**：新建任务默认以 `NT AUTHORITY\SYSTEM` 账户运行，因此不能仅凭运行账户或 Author 是否包含 `SYSTEM` 来判断，而必须依据命名空间路径 `\Microsoft\` 和 Windows 本地化资源前缀 `$(@`，避免误判用户自己创建的系统权限任务。

### 2. 策略持久化模型 (`AuditPolicyStore`)
- 存储文件：`logs/audit_policy.json`（与按月审计日志文件同目录）。
- 数据结构：`Overrides map[string]bool`，键为小写规范化后的完整任务路径。
- 判定优先级：
  1. 若 `Overrides` 中存在该任务路径的明确覆盖值，直接采用该覆盖值；
  2. 否则回退至分类默认值：自定义任务返回 `true`，系统级任务返回 `false`。
- 状态文案（`auditStatusText`）：
  - 自定义任务默认：`已开启(默认)`
  - 手动开启（含系统任务）：`已开启(手动)`
  - 系统任务默认：`未开启(系统默认)`
  - 手动关闭：`已关闭(手动)`

### 3. 界面展示与交互联动
- **主列表 ListView**：在第 3 列（`状态` 之后）插入 `日志审计` 列（宽度 116），加载和切换状态时实时更新，无需横向滚动即可一目了然。
- **工具栏操作按钮**：在 `删除` 按钮右侧新增 `toggleAuditButton`（`开启审计` / `关闭审计`），根据当前选中任务的审计状态动态切换按钮文本；最小窗口宽度 `1080` 下无布局重叠。
- **筛选下拉框 (`statusCombo`)**：扩展为 `全部状态`、`仅启用`、`仅禁用`、`仅自定义任务`、`仅系统任务`、`仅已开审计`。
- **任务加载自动启用通道**：`msgTasksLoaded` 触发时，若至少存在一条 `isTaskAuditEnabled(task) == true` 的任务且具备管理员权限，则在后台异步检查并开启 `Microsoft-Windows-TaskScheduler/Operational` 通道。
- **运行历史与导出门控**：未开启审计的系统级任务切换到“运行历史”时提示手动开启；点击“导出日志”针对未开启审计的选中任务时弹窗询问是否立即手动开启并导出。

## Risks / Trade-offs

- **[Risk]** 修改或重命名任务后，原任务路径的手动覆盖策略可能成为孤立键。
  - **Mitigation**：在 `saveTaskConfig` 成功保存（含改名）以及删除任务时同步更新/清理 `AuditPolicyStore` 并写入磁盘。
- **[Risk]** 标准权限启动时无法调用 `wevtutil sl ... /e:true`。
  - **Mitigation**：后台自动启用前先校验 `isElevated()`，非管理员时静默跳过并在用户手动点击“开启审计”或“启用历史”时给出明确的管理员权限提示。
