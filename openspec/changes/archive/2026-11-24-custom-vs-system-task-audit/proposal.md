# Proposal

## Why

目前仅在通过向导新建或修改任务时才会默认开启日志审计，对于系统中**已经存在的用户自定义定时任务**尚未批量纳入默认日志审计范围；而系统中存在大量 Windows 内置系统级任务（如 `\Microsoft\Windows\...`），若全部纳入审计会产生冗余噪声。因此需要将“自己设置的定时任务”与“系统级定时任务”自动区分：自定义任务全部默认开启日志审计，系统级任务保留默认（未开启），并支持用户在有需要时手动一键开启或关闭。

## What Changes

- **自动识别任务归属类型（`isSystemTask`）**：
  - 将位于 `\Microsoft\` 路径下或作者为系统内置资源字符串（`$(@...`）的任务判定为“系统级定时任务”；
  - 其余根目录或自定义目录中的任务判定为“自己设置的定时任务（自定义任务）”。
- **差异化默认审计策略与持久化配置（`logs/audit_policy.json`）**：
  - 所有**自定义任务**默认全部开启日志审计（`true`）；
  - 所有**系统级任务**默认保留不开启状态（`false`）；
  - 支持用户对任意任务手动切换开启/关闭，并将手动覆盖配置持久化保存至 `logs/audit_policy.json`。
- **任务列表加载时的底层通道自动启用**：
  - 加载任务列表后，若检测到存在已开启日志审计的任务（包含任意自定义任务或手动开启的系统任务）且系统 `Microsoft-Windows-TaskScheduler/Operational` 通道尚未开启，则在后台自动开启该通道并写入操作审计记录；若仅有未开启审计的系统任务，则保持系统通道默认状态不变。
- **界面可视化展示与手动切换入口**：
  - 主列表新增“日志审计”列，直观显示各任务的审计状态（如 `已开启(默认)`、`已开启(手动)`、`未开启(系统默认)`、`已关闭(手动)`）。
  - 选中任务工具栏新增 **`[开启审计]` / `[关闭审计]`** 切换按钮，方便按需手动开启系统级任务的日志审计。
  - 任务筛选下拉框增加 `仅自定义任务`、`仅系统任务`、`仅已开审计` 快捷过滤选项。
  - “运行历史”面板对未开启审计的系统级任务展示明确引导，提示用户可通过点击 `[开启审计]` 按需开启。

### Modified Capabilities

## Impact

- `task_audit.go`：`AuditPolicyStore`（`logs/audit_policy.json`）持久化读写、`isSystemTask` 与审计状态判定。
- `main.go`：列表列展示、筛选选项、`[开启审计]`/`[关闭审计]` 按钮、任务加载自动启用通道、向导与修改/重命名/删除同步更新策略。
- `task_audit_test.go` & `main_test.go`：任务分类、默认策略、手动覆盖持久化与筛选逻辑单元测试。
