# task-log-stream Specification

## Purpose
提供 Windows 定时任务的生命周期全链路日志追踪能力，包括任务创建时间的解析与展示、基于系统底层事件日志的执行历史流查询，以及对管理器自身运维操作的轻量化本地结构化审计记录。

## Requirements

### Requirement: 任务创建时间解析与展示
系统 SHALL 从任务计划程序的原生 XML 定义中的 `RegistrationInfo.Date` 字段解析任务创建时间，并在主界面任务列表及任务详情面板中展示该时间。

#### Scenario: 成功解析并展示任务创建时间
- **WHEN** 任务计划程序中的任务 XML 包含有效的 `RegistrationInfo.Date` 字段（如 `2026-07-21T10:30:00`）
- **THEN** 系统解析该 ISO-8601 字符串并格式化为标准时间格式，在主列表“创建时间”列和详情视图中正确展示

#### Scenario: 任务 XML 缺少创建时间字段
- **WHEN** 某些旧版系统内置任务或精简任务 XML 未包含 `RegistrationInfo.Date` 节点
- **THEN** 系统将其优雅显示为“-”或未知，不阻塞任务列表加载及正常管理操作

### Requirement: 本地管理运维操作审计流
系统 SHALL 将本管理工具内执行的创建、修改、删除、启动、停止、导入等管理操作，以 JSON Lines 格式异步追加记录至本地按月份拆分的日志文件中（格式为 `logs/audit_YYYY-MM.jsonl`），并支持跨月份文件的倒序检索与合并读取。

#### Scenario: 手动触发或修改任务时写入审计日志
- **WHEN** 运维人员通过本工具创建新任务、修改配置或点击“运行”按钮
- **THEN** 系统异步向当前月份对应的 `logs/audit_YYYY-MM.jsonl` 追加一条包含操作时间戳、操作人、动作类型、目标任务路径和执行结果的 JSON 记录，且不阻塞主 UI 线程响应

#### Scenario: 按月份自动拆分写入操作审计日志
- **WHEN** 系统产生新的操作审计事件且跨入新的自然月
- **THEN** 系统自动切换写入至新月份命名的 `logs/audit_YYYY-MM.jsonl` 文件中，历史月份文件保持独立归档

#### Scenario: 跨月份倒序聚合读取与旧版文件兼容
- **WHEN** 用户在界面查看“操作审计”或触发导出全部审计记录
- **THEN** 系统自动扫描 `logs/` 目录下所有匹配的按月拆分文件及历史 `audit.jsonl`，按时间从最新到最旧依次聚合读取

### Requirement: 日志流与审计记录导出至 CSV
系统 SHALL 支持将当前选中的任务执行历史流或管理操作审计流导出为标准 CSV 文件，文件编码采用带 BOM 的 UTF-8，以支持在 Microsoft Excel 和文本编辑器中直接查看。系统 SHALL 在导出前提供自定义记录上限输入界面，允许用户输入指定数量，或输入 `0` / `-1` 导出全部记录（不限制数量），并在弹窗中明确展示无限制导出的书写提示。

#### Scenario: 导出当前任务运行历史记录至 CSV
- **WHEN** 用户在主界面处于“运行历史”面板并点击“导出日志”，且选择了导出路径
- **THEN** 系统提取该任务的执行历史记录并写入包含任务名称、开始时间、完成时间、耗时、退出代码、状态及执行程序的 CSV 文件

#### Scenario: 导出管理操作审计记录至 CSV
- **WHEN** 用户在主界面处于“操作审计”面板并点击“导出日志”，且选择了导出路径
- **THEN** 系统提取相关审计记录并写入包含时间、操作人、动作类型、目标任务、执行结果、详细说明及错误信息的 CSV 文件

#### Scenario: 用户指定正整数限制导出记录
- **WHEN** 用户点击“导出日志”并在弹窗中输入正整数（如 500）且确认保存路径
- **THEN** 系统最多提取指定数量（500 条）的最新的运行历史或审计日志写入 CSV 文件

#### Scenario: 用户输入 0 或 -1 进行无限制全量导出
- **WHEN** 用户在条数输入弹窗中输入 `0` 或 `-1` 且确认保存路径
- **THEN** 系统解除数量截断限制，提取全部可查询的历史或审计记录并写入 CSV 文件

#### Scenario: 导出弹窗明确展示不限制规则提示
- **WHEN** 触发“导出日志”弹出条数设置窗口
- **THEN** 界面清晰呈现“输入 0 或 -1 表示导出全部（不限制数量）”的说明提示，输入框默认填入推荐值 200

#### Scenario: 用户取消输入或输入非法数值
- **WHEN** 用户在条数输入弹窗中点击“取消”，或输入非数字字符与不支持的负数并关闭
- **THEN** 系统安全终止导出流程，不弹出文件保存框，也不产生损坏的导出文件

### Requirement: 自定义与系统级任务的差异化默认日志审计策略
系统 SHALL 自动区分用户自定义的定时任务与系统级定时任务（位于 `\Microsoft\` 路径或使用系统内置资源作者标识的任务）：自定义定时任务默认全部开启日志审计，系统级定时任务保留默认不开启状态，并允许用户按需手动开启或关闭任意任务的日志审计且持久化保存配置。

#### Scenario: 自定义定时任务默认全部开启日志审计
- **WHEN** 系统加载任务列表并识别出位于根目录 `\` 或非系统目录的自定义定时任务（且无手动关闭记录）
- **THEN** 这些自定义任务的日志审计状态均默认判定为“已开启”，主列表“日志审计”列显示已开启状态，且若系统事件历史通道尚未启用且具备管理员权限时自动开启底层通道

#### Scenario: 系统级定时任务保留默认未开启状态
- **WHEN** 系统加载任务列表中的系统级定时任务（如 `\Microsoft\Windows\...`）且无手动开启记录
- **THEN** 这些任务的日志审计状态保留为“未开启(系统默认)”，不主动触发通道开启；用户选中其“运行历史”面板时提示可通过“开启审计”手动启用

#### Scenario: 手动开启或关闭指定任务的日志审计并持久化
- **WHEN** 用户选中任意任务（包括系统级任务）并点击“开启审计”或“关闭审计”按钮
- **THEN** 系统将该任务的覆盖配置持久化写入 `logs/audit_policy.json`，异步向操作审计流记录变更动作，并立即刷新列表与详情状态；若开启审计且底层历史通道未启用则一并开启

#### Scenario: 修改或删除任务时同步维护审计策略配置
- **WHEN** 用户修改重命名任务或删除任务，或在向导中勾选/取消日志审计选项后保存
- **THEN** 系统同步更新或迁移 `logs/audit_policy.json` 中对应任务路径的审计策略覆盖记录，避免残留无效条目

### Requirement: 独立后台轮询采集全部定时任务执行日志并按天存储
系统 SHALL 通过后台定时轮询本机任务计划程序状态（不读取系统自带事件日志，不修改原有任务执行命令），捕获本机全部定时任务的运行启动、结束及上次运行时间与退出码变更，按自然天拆分持久化至 `logs/exec_YYYY-MM-DD.jsonl`。

#### Scenario: 捕获短耗时任务在轮询周期内执行完成
- **WHEN** 某定时任务在两次轮询间隔内启动并执行结束，导致 `LastRunTime` 发生变化
- **THEN** 采集器生成一条包含任务名称、开始时间、捕获完成时间、退出码、状态及执行命令的 JSON 记录，并追加写入当天的 `logs/exec_YYYY-MM-DD.jsonl`

#### Scenario: 捕获长耗时任务从运行中到结束的完整过程
- **WHEN** 某定时任务在一次轮询中状态变为“正在运行”，并在后续轮询中恢复为就绪或完成状态
- **THEN** 采集器先记录运行中快照，结束时使用同一 `InstanceID` 写入带估算耗时与最终退出码的完成记录

#### Scenario: 按自然天自动滚动分文件存储与状态基线防重
- **WHEN** 采集器跨自然天持续运行或进程重启后重新启动
- **THEN** 跨天后自动写入新日期命名的 `logs/exec_YYYY-MM-DD.jsonl`，并通过 `logs/monitor_state.json` 持久化基线避免重复记录已落盘的历史运行

### Requirement: 运行历史视图与导出完全基于独立本地日志
系统 SHALL 完全从本地按天日志文件 `logs/exec_YYYY-MM-DD.jsonl` 跨天倒序聚合读取任务运行历史（同一 `InstanceID` 自动合并保留最新状态），用于主界面“运行历史”展示及自定义条数的 CSV 导出。

#### Scenario: 选中任务或全局查看本地运行历史
- **WHEN** 用户在主界面切换至“运行历史”面板（无论是否选中某条任务，也无论该任务是自定义任务还是系统级任务）
- **THEN** 系统不调用 `wevtutil.exe`，直接从 `logs/exec_YYYY-MM-DD.jsonl` 跨天倒序聚合展示最新执行记录

#### Scenario: 导出独立运行历史为 CSV 文件
- **WHEN** 用户处于“运行历史”面板并点击“导出日志”，输入自定义条数或 `0`/`-1` 导出全部
- **THEN** 系统从本地按天日志文件中提取匹配记录并写入带 UTF-8 BOM 的 CSV 文件

### Requirement: 后台静默守护进程、系统托盘常驻与开机自启
系统 SHALL 支持 `--daemon` 无界面后台守护运行模式、桌面系统托盘最小化常驻及一键开机自启配置，并通过全局命名互斥锁避免守护进程与桌面端重复采集。

#### Scenario: 无界面后台守护进程与单实例防重复采集
- **WHEN** 系统以 `--daemon` 模式运行后台采集器，且用户同时打开桌面 GUI 界面
- **THEN** 守护进程持有全局采集互斥锁持续采集日志；桌面端检测到互斥锁已被占用时不再启动重复轮询，并在界面状态中显示后台采集运行中

#### Scenario: 桌面关闭最小化到系统托盘并支持唤醒与彻底退出
- **WHEN** 用户点击主窗口关闭按钮（X）
- **THEN** 窗口隐藏至右下角系统托盘并保持后台常驻；双击托盘图标或再次启动程序时恢复显示主窗口，通过托盘右键菜单“退出程序”可彻底退出

#### Scenario: 一键开启或关闭开机自启
- **WHEN** 用户在主界面或托盘右键菜单点击切换“开机自启”
- **THEN** 开启时注册 `SYSTEM / ONSTART` 后台守护计划任务（确保服务器重启无人登录时仍可采集）并配置当前用户登录托盘自启；关闭时清理上述计划任务与自启项
